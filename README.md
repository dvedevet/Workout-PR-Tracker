# Workie

Уеб приложение за проследяване на тренировки и лични рекорди (PR). Записваш серии, тежести и повторения, а приложението пази историята и показва прогреса ти под формата на графика.

**Разгледай приложението: https://workieapp.vercel.app**

## Функции

- **Регистрация и вход** с имейл и парола. Паролата е поне 8 символа, с главна буква, малка буква и цифра. Имейлът се потвърждава чрез връзка от писмо.
- **Тренировка:** избираш упражнения от списъка (или добавяш свои), записваш серии с тежест и повторения. При нов рекорд се показва значка.
- **Графици:** шаблони за тренировки, които зареждаш с едно натискане.
- **История:** всички записани тренировки; могат да се изтриват.
- **Прогрес:** графика на прогнозния 1RM (формула на Epley) и максималната тежест за всяко упражнение.
- **Профил:** име, тегло, височина и профилна снимка с редактор.
- **Лични данни:** всеки потребител вижда само своите тренировки, графици и упражнения. 26-те готови упражнения са общи за всички.

## Технологии

| Част | Технология |
|---|---|
| Frontend | React 19, Vite, Tailwind CSS v4, Recharts, lucide-react |
| Backend | .NET 9 Minimal API, Entity Framework Core |
| База данни и вход | Supabase (PostgreSQL и Supabase Auth) |
| Имейли | Brevo (SMTP) |
| Хостинг | Vercel (frontend), Azure App Service (API) |
| Деплой | GitHub Actions (само за API-то) |

## Архитектура

```
Браузър (React, Vercel)
   │  1. вход / регистрация
   ├──────────────► Supabase Auth ──► връща JWT токен
   │
   │  2. заявки с  Authorization: Bearer <токен>
   └──────────────► .NET API (Azure) ──► Supabase PostgreSQL
                       │
                       └─ проверява токена (подпис, издател, срок)
                          и взима потребителя от полето "sub"
```

- Frontend говори директно със Supabase само за вход и регистрация.
- Всички данни минават през API-то. То проверява JWT токена и филтрира данните по потребител, така че не може да се прочетат чужди записи.
- Имейлите за потвърждение се изпращат от Supabase през Brevo.

## API

Всички маршрути започват с `/api` и изискват токен.

| Метод | Маршрут | Какво прави |
|---|---|---|
| GET | `/me` | Данни за текущия потребител |
| GET | `/profile` | Профил (тегло, височина, снимка) |
| PUT | `/profile` | Записва тегло и височина |
| PUT | `/profile/photo` | Записва или премахва снимката |
| GET | `/exercises` | Списък с упражнения (общи и свои) |
| POST | `/exercises` | Добавя ново упражнение |
| GET | `/exercises/{id}/progress` | Прогрес по упражнение |
| GET | `/workouts` | История на тренировките |
| POST | `/workouts` | Записва тренировка |
| DELETE | `/workouts/{id}` | Изтрива тренировка |
| GET | `/plans` | Списък с графици |
| POST | `/plans` | Създава график |
| PUT | `/plans/{id}` | Променя график |
| DELETE | `/plans/{id}` | Изтрива график |

Чужд запис се връща като 404, а липсващ или невалиден токен като 401.

## База данни

Таблици: `exercises`, `workouts`, `workout_sets`, `plans`, `plan_exercises`, `profiles`. Всички, освен общите упражнения, имат `user_id`.

## Деплой

- **Frontend:** Vercel го публикува автоматично при push към `main`. Променливите `VITE_` се четат при билд, затова след промяна на стойност трябва нов деплой.
- **API:** GitHub Actions го публикува в Azure при всеки push към `main`.
- **CORS:** сайтовете, които могат да викат API-то, се задават в `Cors:AllowedOrigins`..

## Потвърждение на имейл

- Supabase изпраща писмата през собствен SMTP сървър (Brevo), защото вграденият праща само до членове на проекта.
- Включено е "Confirm email", а шаблонът "Confirm sign up" е на български.
- В Supabase са зададени Site URL (`https://workieapp.vercel.app`) и Redirect URLs за локална работа.
- Правилото за паролата (8 символа, главна, малка буква и цифра) е зададено и в Supabase, не само във формата.
